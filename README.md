# أرسل لنفسي — send-to-self

صندوقك الشخصي: أرسل لنفسك نصوصًا وصورًا وفيديو وصوت وملفات (حتى الضخمة منها) من أي جهاز — بكلمة مرور واحدة فقط. يتحدّث تلقائيًا بين أجهزتك.

## وش الجديد في هذي النسخة؟

1. **رفع مجزّأ قابل للاستئناف** — الملف يتقسّم أجزاء 8MB تُرفع بالتوازي وتُجمَّع على السيرفر بتيار مباشر إلى التخزين. معناها:
   - ملف **بأي حجم** (حتى 2GB افتراضيًا) يرفع على سيرفر ذاكرته 512MB بدون انفجار. هذا بالضبط سبب فشل رفع الكتاب الدراسي سابقًا — الرفع القديم كان يحمّل الملف كله في الذاكرة.
   - لو انقطع النت، اضغط "إرسال" مرة ثانية — يكمل من آخر جزء وصل، ما يرفع من الصفر.
2. **درايفر MEGA محصّن** — مانع تكرار تسجيل الدخول (circuit breaker) يمنع قفل الحساب، مع رسائل عربية واضحة: (حساب مقفل / مساحة ممتلئة / كوتة النقل استُنفدت / بيانات الدخول غلط).
3. **مؤشر حالة التخزين** في الواجهة — تعرف فورًا إذا MEGA متعذّر بدل ما تفشل الرفعات بصمت.
4. **`/api/health` موسّعة** — `db + storage` (استخدمها هدفًا لإبقاء السيرفر مستيقظًا، انظر الأسفل).

## ليش MEGA قفل حسابك؟ (التشخيص)

- تطبيقك يسجّل دخول لحساب MEGA **برمجيًا بكلمة المرور** من IP داتا سنتر (Render).
- الخطة المجانية في Render **تنام بعد 15 دقيقة خمول** → كل صحيان = تسجيل دخول جديد كامل، من IP سحابي متغيّر ومشترك، عبر مكتبة غير رسمية (megajs).
- نظام الحماية عند MEGA يقرأ هذا النمط كـ **"malicious login"** → يقفل الحساب "حمايةً لك".
- بعد القفل، كل عملية رفع تفشل لأن تسجيل الدخول نفسه يُرفض — عشان كذا "بطّل يرفع"، بينما النصوص ظلت تشتغل (تنحفظ في قاعدة البيانات).
- ملاحظة ثانية: كوتة نقل MEGA المجانية (~5GB لكل 6 ساعات **لكل IP**) والـ IP عند Render مشترك — ممكن تنفد بسببك أو بسبب غيرك. الكود الآن يكشفها ويوضحها لك (خطأ EAGAIN/-18).

### الحل الفوري (فك القفل الآن)

1. افتح إيميل MEGA → رسالة القفل → **Resend email / رابط إعادة التعيين** → باسورد جديد.
2. في Render → **Environment** → حدّث `MEGA_PASSWORD` بالجديدة → Save (يعيد النشر تلقائيًا).
3. جرّب الرفع — المؤشر في الواجهة يجب يصير **"MEGA متصل"**.

### تقليل تكرار المشكلة

- **أبقِ السيرفر مستيقظًا**: سجّل في [cron-job.org](https://cron-job.org) مجانًا وأنشئ مهمة تنادي
  `https://sending-to-self.onrender.com/api/health` كل **10 دقائق**.
  قلة النوم = قلة إعادة تسجيل الدخول = خطر قفل أقل بكثير.

### الحل الجذري (موصى به): انتقل إلى Cloudflare R2

كودك أصلًا فيه درايفر S3 جاهز — التبديل كله **متغيرات بيئة فقط، بدون أي تعديل كود ولا رفع على GitHub**:

1. أنشئ حساب [Cloudflare](https://dash.cloudflare.com) (مجاني) → **R2** → Create bucket (مثلًا `send-to-self`).
2. R2 → **Manage R2 API Tokens** → Create Token (صلاحية Read & Write) → خُذ:
   `Access Key ID` + `Secret Access Key`، وانقل أيضًا **Account ID**.
3. في Render → Environment أضف/عدّل:
   - `STORAGE_DRIVER=s3`
   - `S3_BUCKET=send-to-self`
   - `S3_ACCESS_KEY_ID=...`
   - `S3_SECRET_ACCESS_KEY=...`
   - `S3_ENDPOINT=https://<ACCOUNT_ID>.r2.cloudflarestorage.com`
4. احذف متغيرات `MEGA_*` أو اتركها (درايفر S3 له الأولوية مع `STORAGE_DRIVER=s3`).

R2: **10GB مجانًا دائمًا + صفر رسوم نقل + مفاتيح API (ما فيه حساب ينقفل)**. الملفات القديمة في MEGA ما تنتقل تلقائيًا — حمّلها وأعد رفعها إن تبغاها.

## متغيرات البيئة (Render → Environment)

| المتغير | إجباري؟ | الوظيفة |
|---|---|---|
| `DATABASE_URL` | ✅ | رابط Postgres (النصوص وفهرس الملفات) |
| `DEFAULT_PASSWORD` | ✅ | كلمة المرور الأولى — غيّرها من داخل التطبيق لاحقًا |
| `STORAGE_DRIVER` | — | `mega` / `s3` / `local` (تلقائي إن تُرك فارغًا) |
| `MEGA_EMAIL` + `MEGA_PASSWORD` | خيار 1 | دخول حساب MEGA (مجاني 20GB) |
| `MEGA_FOLDER` | — | اسم المجلد داخل MEGA (افتراضي `send-to-self`) |
| `S3_BUCKET` + `S3_ACCESS_KEY_ID` + `S3_SECRET_ACCESS_KEY` + `S3_ENDPOINT` | خيار 2 | تخزين S3/R2 (مجاني 10GB، موصى به) |
| `S3_PREFIX` | — | بادئة المفاتيح (افتراضي `uploads/`) |
| `NEXT_PUBLIC_MAX_FILE_MB` | — | الحد الأقصى لحجم الملف (افتراضي `2048`) — بعد التغيير أعد البناء |

```bash
npm install

npm run dev            # http://localhost:3000
```

## رفع التعديلات على GitHub (بنفسك، أسهل من ما تتوقع)

ما يحتاج أحد يدخل حسابك — ثلاث طرق، أي واحدة تكفي:

**أ) من جهازك (أدق طريقة):**
```bash
git clone https://github.com/immmh5/sending-to-me
cd sending-to-me
# انسخ ملفات هذه النسخة فوق الملفات القديمة، ثم:
git add -A && git commit -m "chunked uploads + hardened MEGA driver" && git push
```
Render ينشر تلقائيًا بعد كل push.

**ب) GitHub Desktop** (بدون أوامر): Clone المستودع → استبدل الملفات → Commit → Push.

**ج) من متصفح GitHub مباشرة**: افتح الملف في المستودع → أيقونة القلم (Edit) → استبدل المحتوى → Commit changes. مناسبة لتعديل ملفات قليلة.

## بنية الرفع الجديدة

```
المتصفح                                السيرفر
────────                               ────────
start (name,size) ───────────────▶ POST /api/upload/start      → uploadId
أجزاء 8MB ×3 بالتوازي ──────────▶ PUT  /api/upload/part?i=…     → تخزين مؤقت على القرص
(استئناف: GET /part يرد بالأجزاء المستلمة فيتخطاها العميل)
complete ───────────────────────▶ POST /api/upload/complete     → تجميع بتيار → MEGA/S3/قرص (+ثمبنيل)
إنشاء العنصر ────────────────────▶ POST /api/upload (JSON خفيف) → قاعدة البيانات → بث SSE للأجهزة
```

الذاكرة على السيرفر ثابتة (~أجزاء قليلة بالمرة الواحدة) مهما كبر الملف.
